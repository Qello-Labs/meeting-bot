# n8n 워크플로

이 폴더의 워크플로 JSON은 n8n 컨테이너의 `/workflows`에 읽기 전용으로 연결된다(`docker-compose.yml`).

| 워크플로 | 파일 | 단계 |
| --- | --- | --- |
| 회의 녹취 | `meeting-transcribe.json` | 설계 문서 9절 5~9단계 |
| 회의 녹취 실패 알림 | `meeting-transcribe-failure.json` | 설계 문서 9절 10단계(#23) |

## 원본은 코드다

JSON을 직접 고치지 않는다. Code 노드 코드는 `workflows/src/*.js`에, 노드 구성은 `scripts/build-workflow.js`에 있고
JSON은 스크립트가 만든다. 여러 Code 노드가 같이 쓰는 코드는 `workflows/src/shared/`에 두고 빌드 스크립트가 노드 코드 앞에 붙인다
(n8n Code 노드는 다른 파일을 가져올 수 없다). 근거 검증 규칙(`draft-rules.js`)은 초안 검증과 결정 읽기가, 버튼(`approval-buttons.js`)은
초안 메시지 만들기, 수정 반영 만들기, 결정 읽기가 같이 쓴다.

```bash
node scripts/build-workflow.js           # workflows/*.json 다시 만들기
node scripts/build-workflow.js --check   # 커밋된 JSON이 코드와 같은지 확인(npm test에도 들어 있다)
```

n8n 화면에서 보고, 실행하고, 임시로 고치는 것은 자유다. 확정한 수정은 코드로 옮긴다. 놓치지 않도록 화면에서 내려받은 JSON을
저장소 JSON과 비교한다.

```bash
node scripts/diff-workflow.js <화면에서 내려받은 JSON>
```

노드 이름 기준으로 `type`, `typeVersion`, `parameters`, 노드 설정(재시도 등), 연결만 비교한다. 위치, ID, 자격 증명은 무시한다.
단, 한 노드에서 갈라진 갈래들의 위아래 순서는 실행 순서를 정하므로 비교한다.
n8n 화면에서 저장하면 기본값과 같은 파라미터가 JSON에서 빠진다(안쪽 설정과 배열 항목 안의 값도 빠진다). 이 값들은
`diff-workflow.js`의 기본값 표로 같게 본다. 새 노드를 쓰면 화면에서 저장해 보고 빠지는 값을 표에 더한다.
차이가 없으면 0, 있으면 1로 끝난다.

## 회의 녹취

녹음 봇이 회의를 끝내면 manifest를 `http://n8n:5678/webhook/meeting-ended`로 보낸다.

```
                    ┌─ 결정 메시지 기간 → 결정 메시지 조회 → 결정 메시지 고르기 ─┐ (위)
… → 발화 파일 확인 ─┤                                                          ├→ 녹취·결정 합치기 ─┐
                    └─ 음성 인식 → 녹취 만들기 ────────────────────────────────┘ (아래)            │
  ┌──────────────────────────────────────────────────────────────────────────────────────────────┘
  └→ 템플릿 읽기 → 초안 요청 만들기 → 초안 작성 → 초안 검증 → 알림 만들기 → 회의 채널 알림 ─┐
  ┌───────────────────────────────────────────────────────────────────────────────────────────┘
  │                                          ┌─ (참) 초안 보내기(첨부) ─┐
  └→ 초안 메시지 만들기 → 긴 초안 확인 ───────┤                          ├→ 승인 기다리기 ◀──────────────────────┐
                                             └─ (거짓) 초안 보내기 ─────┘        │                                    │
  ┌──────────────────────────────────────────────────────────────────────────────┘                                    │
  └→ 결정 읽기 → 기한 초과 확인 ─(참)─────────────────────────────────────┐                                         │
                      └─(거짓)→ 결정 응답 → 승인·거절 확인 ─(참)──────────┤                                         │
                                              └─(거짓)→ 수정 확인 ─(참)→ 수정 반영 만들기 → 수정 반영 ──────────────┤
                                                            └─(거짓: 이미 바뀜, 검증 실패)───────────────────────────┘
  ┌───────────────────────────────────────────────────────────────────────┘
  └→ 결과 표시 ─┬─(위)→ 쓰기 준비 → 같은 제목 찾기 → 쓰기 판단 → 같은 이름 확인 ─(참)──────────────────┐
               │                                                       └─(거짓)→ 액션 아이템 고르기 ─┐       │
               │  ┌──────────────────────────────────────────────────────────────────────────────┘       │
               │  └→ 같은 회의 이슈 찾기 → 스프린트 읽기 → 이슈 요청 만들기 → 새 이슈 확인 ─(참)→ Jira 이슈 만들기 ─┐  │
               │                                                              └─(거짓)──────────────────────┤  │
               │  ┌───────────────────────────────────────────────────────────────────────────────────────┘  │
               │  └→ 회의록에 이슈 채우기 → 페이지 만들기 → 페이지 다시 읽기 → 내용 대조 ─────────────────────┴→ 쓰기 결과 표시
               └─(아래)→ 기한 초과 알림 만들기 → 기한 초과 알림
```

| 노드 | 하는 일 |
| --- | --- |
| 회의 종료 (Webhook) | manifest를 받자마자 응답한다. 음성 인식이 길어도 녹음 봇 요청이 끊기지 않게 하기 위해서다 |
| 녹음 정보 확인 (Code) | 회의 ID, 파일 이름, 서버·채널 ID 형식을 확인한다. 경로와 Discord 요청에 들어가는 값이라 형식이 맞는 것만 받는다 |
| 발화 목록 (Code) | 발화마다 `/recordings/<회의 ID>/segments/<파일>` 경로를 만든다 |
| 발화 파일 읽기 | 파일을 읽는다. 파일이 없으면 오류 없이 0건을 내므로(n8n 2.42.6) 다음 노드가 확인한다 |
| 발화 파일 확인 (Code) | 읽은 파일의 개수와 순서가 발화 목록과 다르면 실패시킨다 |
| 결정 메시지 기간 (Code) | 지난 회의 끝 시각(워크플로 static data, 9단계에서 갱신)부터 이번 회의 종료까지를 Discord 메시지 ID로 바꾼다. 저장값이 없거나 이상하면 회의 시작 7일 전부터 본다 |
| 결정 메시지 조회 (HTTP Request) | 회의 채널 메시지를 기간 시작 ID(`after`)부터 100개씩 받는다. 100개 미만이거나 회의 종료를 넘으면 멈추고, 요청은 50번까지 한다 |
| 결정 메시지 고르기 (Code) | 기간 안에 사람이 쓴 메시지(봇·Webhook·시스템 메시지 제외) 중 ✅ 반응이 1개 이상인 것만 고른다. 링크, 표시 이름, 내용, 첨부 이름, 시각을 남기고 작성자 ID는 남기지 않는다 |
| 음성 인식 (HTTP Request) | OpenAI `gpt-4o-transcribe`. 언어 `ko`, 참석자 이름을 프롬프트로 넘긴다. 5개씩 보내고 실패하면 노드 전체를 3번까지 다시 시도한다 |
| 녹취 만들기 (Code) | `[HH:MM:SS] 화자: 내용`을 시각 순으로 합치고 끊긴 구간을 끼워 넣는다. 녹취는 n8n 실행 기록(7일 보관)에만 남는다 |
| 녹취·결정 합치기 (Merge) | 두 갈래가 모두 끝날 때까지 기다렸다가 빈 항목 하나로 넘긴다 |
| 템플릿 읽기 (HTTP Request) | Confluence v2로 `회의록 템플릿` 페이지를 저장 형식(`body-format=storage`)으로 읽는다. 사이트 주소와 페이지 ID는 코드 상수다. 실패하면 3번까지 다시 시도한다 |
| 초안 요청 만들기 (Code) | 템플릿 저장 형식을 Markdown으로 바꾼다(`shared/confluence-format.js`). 템플릿, 녹취, 결정 메시지를 태그로 감싸 데이터로만 넘기는 OpenAI Responses API 요청을 만든다(`gpt-6-luna`, effort `high`, `store: false`) |
| 초안 작성 (HTTP Request) | OpenAI `POST /v1/responses`. 음성 인식과 같은 자격 증명. 연결·HTTP 오류는 3번까지 다시 시도한다 |
| 초안 검증 (Code) | 응답이 잘리거나 거절이면 실패시킨다. 고정 필드를 덮어쓰고, 날짜·명세 ID를 정리하고, 구조와 근거를 검증해 `draftOk`와 오류 목록을 낸다 |
| 알림 만들기 (Code) | `회의 <회의 ID> 녹취 완료, 발화 N개, 결정 메시지 M개, 초안 검증 통과`(또는 `초안 검증 실패(오류 종류별 개수)`)를 만든다 |
| 회의 채널 알림 (Discord) | 위 문구만 회의 채널에 보낸다 |
| 초안 메시지 만들기 (Code) | 검증을 통과한 초안만 승인 메시지(1판)로 만든다(실패하면 항목을 내지 않아 여기서 끝난다). embed, `승인`·`수정`·`거절` 버튼(`수정`은 4,000자 이하만), 멘션 끄기. 4,096자를 넘으면 `.md` 파일을 붙인다 |
| 긴 초안 확인 (If) | 파일을 붙일 초안이면 참 갈래로 보낸다 |
| 초안 보내기(첨부), 초안 보내기 (HTTP Request) | 회의 채널에 초안을 보낸다(multipart로 파일 첨부 / JSON). 다시 보내면 두 번 올라가므로 재시도하지 않는다 |
| 승인 기다리기 (Wait) | 녹음 봇이 버튼 클릭을 재개 주소로 보낼 때까지 최대 3일 기다린다. 판단은 결정 응답 노드가 답한다(응답 방식 `responseNode`) |
| 결정 읽기 (Code) | 재개 요청의 `{ decision, rev, by, draft? }`를 읽는다. 본문이 없으면 기한 초과, 판 번호가 지금 판과 다르면 이미 바뀜이다. 고친 초안은 초안 검증과 같은 규칙으로 다시 검증한다 |
| 기한 초과 확인, 승인·거절 확인, 수정 확인 (If) | 결정 읽기의 `outcome`으로 갈래를 나눈다. 기한 초과는 응답할 요청이 없어 결정 응답을 거치지 않는다 |
| 결정 응답 (Respond to Webhook) | 녹음 봇에 `accepted`, `stale`, `invalid`(오류 종류별 개수)를 JSON으로 답한다. 승인은 Confluence 쓰기를 기다리지 않고 먼저 답한다 |
| 수정 반영 만들기 (Code), 수정 반영 (HTTP Request) | 같은 초안 메시지를 고친 초안, `(수정: 이름)`, 판 번호를 올린 버튼으로 바꾸고 다시 기다린다 |
| 결과 표시 (HTTP Request) | 초안 메시지의 버튼을 지우고 `승인(이름). Confluence에 쓰는 중`, `거절(이름)`, `기한 초과`를 적는다 |
| 쓰기 준비 (Code) | 승인일 때만 Confluence에 쓸 제목(`YYYY-MM-DD 정기 회의`)과 저장 형식으로 바꾼 본문을 만든다. 보낸 Markdown은 대조용으로 남긴다. 상위 페이지 ID가 비면 실패한다 |
| 같은 제목 찾기 (HTTP Request) | `GET /pages?space-id&title`로 Qello 스페이스에서 같은 제목의 페이지를 찾는다. Confluence는 스페이스 안에서 제목이 겹칠 수 없다 |
| 쓰기 판단 (Code), 같은 이름 확인 (If) | 검색 응답 형식이 다르면 멈추고, 같은 제목이 있으면 쓰지 않고 이유를 적는다 |
| 액션 아이템 고르기 (Code) | 승인본의 `## 액션 아이템` 표에서 할 일이 있는 행(비었거나 `없음`·`-`가 아닌 것)을 고른다. 이슈 칸에 이미 `SCRUM-N` 키가 있으면 그 키를 쓴다 |
| 같은 회의 이슈 찾기 (HTTP Request) | Jira `GET /rest/api/3/search/jql`로 `meeting-<회의 ID>` 레이블 이슈를 찾는다. 다시 처리할 때 요약이 같은 이슈를 새로 만들지 않는 데 쓴다 |
| 스프린트 읽기 (HTTP Request) | `GET /rest/agile/1.0/board/1/sprint?state=active,future`로 진행 중·예정 스프린트를 읽는다 |
| 이슈 요청 만들기 (Code), 새 이슈 확인 (If) | 행마다 `작업` 이슈 요청을 만든다. 담당 파트 이름으로 시작하는 스프린트 중 기한이 기간 안에 드는 것 하나에 넣고(스프린트 필드), 아니면 백로그에 둔다. 만들 것이 없으면 만들기를 건너뛴다 |
| Jira 이슈 만들기 (HTTP Request) | `POST /rest/api/3/issue`. 다시 보내면 이슈가 두 개 생길 수 있어 재시도하지 않는다 |
| 회의록에 이슈 채우기 (Code) | 만든 이슈와 이미 있던 이슈의 키를 표의 Jira 이슈 칸에 링크로 채우고, Confluence에 쓸 요청을 다시 만든다 |
| 페이지 만들기 (HTTP Request) | `회의록` 아래에 페이지를 만든다(`POST /pages`, `representation: storage`). 응답을 못 받고 다시 보내면 결과를 알 수 없어 재시도하지 않는다 |
| 페이지 다시 읽기 (HTTP Request), 내용 대조 (Code) | 만든 페이지를 저장 형식으로 다시 읽어 Markdown으로 바꾼 뒤 제목, 상위 페이지, 본문 줄을 대조하고 지난 회의 끝 시각을 갱신한다 |
| 쓰기 결과 표시 (HTTP Request) | 초안 메시지에 페이지 링크, 대조 결과, 만든·연결한 Jira 이슈 키(또는 같은 이름이라 쓰지 않은 이유)를 적는다 |
| 기한 초과 알림 만들기 (Code), 기한 초과 알림 (HTTP Request) | 기한 초과일 때만 초안 메시지에 답장으로 알린다 |

- 음성 인식은 OpenAI 전용 노드가 아니라 HTTP Request 노드를 쓴다. n8n 2.42.6의 OpenAI 노드는 음성 인식 모델이 `whisper-1`로
  고정이고 프롬프트를 받지 않는다. 같은 테스트 녹음으로 비교한 결과는 [결정 기록](../docs/decisions/2026-10-11-gh13-transcription-nodes.md)에 있다.
- Discord 노드에는 멘션을 끄는 옵션(`allowed_mentions`)이 없다. 그래서 알림 문구를 코드가 만든 회의 ID와 숫자로만 채운다.
  녹취나 오류 문구처럼 사람이 쓴 글이 들어가는 메시지에는 이 노드를 쓰지 않는다.
- 노드 전체를 다시 시도하므로 발화 하나만 실패해도 회의 전체 발화를 다시 보낸다(E2E: 발화 6개에 요청 1건 실패 → 요청 12건).
- n8n(executionOrder v1)은 갈래를 동시에 돌리지 않고 화면 위쪽 갈래부터 하나씩 끝까지 실행한다. 결정 메시지 갈래를 위에 두어
  Discord 쪽이 실패하면 음성 인식(유료) 전에 멈춘다. 화면에서 두 갈래의 위아래를 바꾸지 않는다(차이 검사가 찾는다).
- 결정 메시지는 ✅ 반응으로 표시한다. 메시지 본문의 ✅는 보지 않는다(`AGENTS.md` 3.2).
- 다음 경우에는 결정이 조용히 빠지지 않게 실행을 실패시킨다.
  - 조회가 실패했다. 페이지 넘김 중 오류 응답을 받으면 n8n 2.42.6이 오류 본문을 출력으로 내고 성공으로 끝낼 수 있어서,
    페이지 넘김 식이 오류 응답에서도 깨지지 않게 하고 고르기 노드가 메시지가 아닌 항목을 거부한다.
  - 요청 50번(5,000개)으로 회의 종료에 닿지 못했다.
  - ✅ 메시지의 내용과 첨부가 모두 비었다. Message Content Intent가 꺼져 있으면 이렇게 온다.
- 초안 검증(설계 5절 F):
  - 구조 기준은 실행 때 읽은 템플릿이다(`##` 제목 이름·순서, 필드 표 첫 열, 액션 아이템 표 머리글). `###` 제목은 개수를 따지지 않는다.
  - `일시`(회의 시작의 한국 날짜), `회의 종류`(`정기 회의`), `참석자`(manifest 이름)는 코드가 덮어쓴다.
  - `결정 사항` 항목은 `*   <결정>. 이유: <이유>. (근거: 녹취 HH:MM:SS, [Discord 메시지](<링크>))` 형식이어야 한다. 녹취 시각은 발화 줄과 정확히
    같아야 하고(녹음 끊김 줄은 안 됨), 링크는 수집한 결정 메시지 링크여야 한다. 수집한 ✅ 메시지는 모두 어느 결정의 근거여야 한다.
    ✅ 메시지가 없을 때만 `*   없음` 한 줄을 허용한다. `<…>` 자리표시자가 남으면 오류다.
  - 기한·다음 회의 일시가 `YYYY-MM-DD`가 아니면 지우고, 입력에 그대로 나오지 않은 명세 ID는 지운다. 지운 값은 `cleaned`에 남기고 알림에 개수를 넣는다.
  - 검증이 실패하면 실행은 성공으로 끝내고 `draftOk: false`로 표시한다. 회의 채널에는 오류 종류별 개수만 알리고 목록과 초안은 실행 기록에만 남긴다.
- 응답 잘림(`incomplete`), 거절(`refusal`), 템플릿 조회 실패, API 오류는 실행을 실패시킨다. 실패하면 설정(`errorWorkflow`)에 적힌
  회의 녹취 실패 알림 워크플로가 회의 채널에 알린다(아래).
- `녹음 정보 확인`은 회의 ID와 채널 ID를, `결정 읽기`는 초안 메시지 ID를 실행의 `customData`에 적는다. 실패 알림이 이 값으로 알릴 곳을 찾는다.
- 승인 버튼(설계 5절 G):
  - 버튼·모달 ID는 `mb:<approve|reject|edit>:<실행 ID>:<판 번호>:<서명>`이다. 실행 ID와 서명은 `$execution.resumeUrl`에서 읽는다.
    n8n 2.42.6 Code 노드에는 `URL`이 없어 정규식으로 읽는다. 같은 실행에서 다시 기다려도 서명이 같아서 판 번호로 옛 버튼을 가른다.
  - 녹음 봇(`src/approval.js`)이 클릭을 받아 `MEETING_ENDED_WEBHOOK_URL`의 origin으로 `/webhook-waiting/<실행 ID>?signature=<서명>`을 부른다.
    서명이 틀리면 401, 끝난 실행은 409다. 재개 주소는 Docker 네트워크 안에서만 열려 있다.
  - `수정`은 녹음 봇이 n8n을 부르지 않고 embed 본문으로 채운 모달을 바로 연다. 모달 ID는 버튼 ID와 같다.
- Confluence 쓰기(설계 5절 H, [결정 기록](../docs/decisions/2026-10-17-gh31-confluence-minutes.md)): 상위 페이지는 Team Docs의 `회의록`이고
  사이트 주소, 스페이스, 페이지 ID는 `scripts/build-workflow.js`의 상수다. Confluence API에는 Markdown이 없어서
  `workflows/src/shared/confluence-format.js`가 Markdown과 저장 형식(XHTML)을 서로 바꾼다. 제목, 문단, 목록, 표, 인용, 구분선, 코드 블록,
  굵게, 인라인 코드, 링크, 줄바꿈만 다루고 매크로(앵커 등)는 지운다. 표의 첫 행은 머리글로 본다.
  다시 읽은 본문은 공백, 목록 기호, 번호 목록의 번호, 표 구분선, 역슬래시 이스케이프, `<br>` 차이를 같은 것으로 본다.
- Jira 이슈(#32, [결정 기록](../docs/decisions/2026-10-17-gh32-jira-action-items.md)): 승인본의 액션 아이템마다 Qello 프로젝트(`SCRUM`)에
  `작업` 이슈를 만든다. 요약은 할 일, 기한은 표의 기한(`YYYY-MM-DD`일 때만), 레이블은 `meeting-minutes`와 `meeting-<회의 ID>`, 설명은 회의록 이름·
  담당 파트·담당자 이름이다. 담당자 칸은 비운다(Jira에 팀원 계정이 없다). 스프린트는 `Backend·Sprint N`처럼 담당 파트 이름으로 시작하는
  진행 중·예정 스프린트 중 기한이 한국 날짜로 기간 안에 드는 것 하나다. 같은 제목의 회의록이 있어 쓰지 않을 때는 이슈도 만들지 않는다.
- 초안 모델을 고른 이유와 데이터 정책은 [결정 기록](../docs/decisions/2026-10-11-gh17-draft-model.md)에 있다.

## 회의 녹취 실패 알림

회의 녹취 실행이 실패하면 n8n이 이 워크플로를 실행한다(설계 5절 "실패 알림").

```
실패 → 실행 읽기 → 알림 만들기 → 실패 알림 → 초안 메시지 확인 ─(참)→ 초안 메시지 고치기
```

| 노드 | 하는 일 |
| --- | --- |
| 실패 (Error Trigger) | 실패한 실행의 ID, 마지막 노드, 오류를 받는다. 실패한 실행의 노드 출력은 받지 않는다(n8n 2.42.6) |
| 실행 읽기 (HTTP Request) | n8n API `GET /api/v1/executions/<ID>?includeData=true`로 실패한 실행을 읽는다. `customData`는 `includeData=true`일 때만 온다. 3번까지 다시 시도하고, 끝내 실패하면 오류 항목을 넘긴다 |
| 알림 만들기 (Code) | 회의 채널, 알림 문구, 초안 메시지 고치기 요청을 만든다. 채널을 모르면 실제 회의 채널(코드 상수)로 보낸다 |
| 실패 알림 (HTTP Request) | 회의 채널에 알린다. 멘션을 끈다. 다시 보내면 두 번 가므로 재시도하지 않는다 |
| 초안 메시지 확인 (If), 초안 메시지 고치기 (HTTP Request) | 승인 버튼이 눌린 뒤 실패했으면 초안 메시지를 `처리 중 실패했습니다(n8n 실행 <ID>)`로 바꾸고 버튼을 지운다 |

- 알림 예: `회의 20261014-1400 회의록 처리가 '초안 작성' 단계에서 실패했습니다. 오류: 외부 서비스 응답 오류(HTTP 429). n8n 실행 123에서 확인해 주세요.`
- 알림에는 코드가 정한 값만 넣는다. 노드 이름은 회의 녹취 워크플로에 있는 이름만, 오류 종류는 HTTP 상태 코드·시스템 오류 코드·`검사 중단`(Code 노드)·`기타 오류`
  중 하나다. 오류 원문, 실행 주소, 요청 본문은 넣지 않는다. 실패(Error Trigger)가 주는 오류에는 녹취·초안이 담긴 요청 본문, 쿼리를 포함한 주소,
  사람이 쓴 글이 섞여 있기 때문이다. 자세한 원인은 실행 ID로 n8n 화면에서 본다.
- `Jira 이슈 만들기`나 그 뒤에서 실패했으면 Jira(`meeting-<회의 ID>` 레이블 이슈)와 Confluence `회의록`에 만들어진 것이 있는지 확인하라고 덧붙인다.
  다시 처리하면 같은 레이블과 요약의 이슈는 새로 만들지 않는다.
- 실행 읽기 결과(녹취·초안 포함)가 이 워크플로의 실행 기록에도 남는다. 같은 n8n DB이고 7일 뒤 함께 지워진다.
- 근거 검증 실패는 실행이 성공으로 끝나므로 이 워크플로가 돌지 않는다. 회의 채널 알림에 오류 종류별 개수가 간다.

## 릴리스 때 자동 반영

릴리스 배포(README "릴리스와 배포")가 이 폴더의 두 JSON을 서버 n8n에 반영한다(`scripts/deploy/apply-workflows.js`,
[결정 기록](../docs/decisions/2026-10-13-gh26-workflow-api-apply.md)). n8n을 멈추지 않고 공개 API로 한다.

1. 자격 증명 목록에서 이름·종류만 읽어, 노드마다 같은 종류의 자격 증명을 붙인다. 종류별로 하나가 아니면(없거나 둘 이상) 반영하지 않고 실패한다.
2. 서버의 정의와 동작이 같으면(노드, 연결, 갈래 순서, 워크플로 설정, 자격 증명 연결) "변경 없음"으로 넘어간다.
3. 다르면 `PUT /workflows/{id}`(지금 static data를 그대로 보냄) → `POST /workflows/{id}/activate` → 켜짐·게시 버전·자격 증명 연결을 확인한다.
   PUT만 하면 Webhook이 옛 정의로 돌아서 activate까지 한다(n8n 2.42.6 실험).
4. 확인에 실패하면 반영 전 정의로 되돌리고 다시 켠 뒤 실패로 끝난다.

실패 알림을 먼저, 회의 녹취를 나중에 반영한다. 승인을 기다리던 실행은 실행에 저장된 옛 정의로 끝나고, 결과에 그 개수를 적는다
(`회의 녹취: 반영 (승인 대기 실행 1개는 옛 정의로 끝남)`). 서버에서 직접 돌릴 때:

```bash
cd /opt/meeting-bot   # .env는 deploy만 읽을 수 있어 deploy로 실행한다
sudo -u deploy bash -c 'N8N_DEPLOY_API_KEY=$(sed -n "s/^N8N_DEPLOY_API_KEY=//p" .env) docker compose run --rm --no-deps -T \
  -e N8N_DEPLOY_API_KEY -v "$PWD/workflows:/app/workflows:ro" recorder node scripts/deploy/apply-workflows.js'
```

## 가져오기(처음 한 번, 또는 수동)

가져오기와 n8n 시작을 동시에 하지 않는다. 처음 만든 DB에서 둘이 함께 마이그레이션을 돌리면 n8n이 `malformed JSON` 오류로 멈춘다
(n8n 2.42.6에서 확인). n8n을 멈춘 상태에서 일회용 컨테이너로 가져온 뒤 n8n을 띄운다.

```bash
docker compose stop n8n
docker compose run --rm --no-deps n8n import:workflow --input=/workflows/meeting-transcribe.json
docker compose run --rm --no-deps n8n import:workflow --input=/workflows/meeting-transcribe-failure.json
docker compose start n8n
```

같은 ID의 워크플로가 있으면 덮어쓰고 꺼진 상태가 된다. 자격 증명 연결도 비워진다. n8n 화면에서 노드마다 자격 증명을 고른 뒤
두 워크플로를 모두 Publish한다. 실패 알림 워크플로도 Publish해야 실행된다(n8n 2.42.6).

실패 알림의 실행 읽기에 쓸 n8n API 키를 n8n마다 만든다.

1. Settings → n8n API에서 API 키를 만든다. 범위(Scopes)를 고를 수 있으면 `execution:read`만 고른다.
2. Credentials에서 Header Auth 자격 증명을 만든다. Name은 `X-N8N-API-KEY`, Value는 1의 키다.
3. 실행 읽기 노드에서 이 자격 증명을 고른다. 주소는 컨테이너 안의 `http://127.0.0.1:5678`이라 바꾸지 않는다.

| 노드 | 자격 증명 |
| --- | --- |
| 음성 인식 | OpenAI (API 키) |
| 결정 메시지 조회 | Discord Bot (녹음 봇과 같은 토큰) |
| 템플릿 읽기 | Basic Auth (Atlassian 계정 이메일 + API 토큰. 아래 참고) |
| 초안 작성 | OpenAI (음성 인식과 같은 것) |
| 회의 채널 알림 | Discord Bot |
| 초안 보내기(첨부), 초안 보내기, 수정 반영, 결과 표시, 쓰기 결과 표시, 기한 초과 알림 | Discord Bot |
| 같은 제목 찾기, 페이지 만들기, 페이지 다시 읽기 | Basic Auth (템플릿 읽기와 같은 것. Qello 스페이스 쓰기 권한 필요) |
| 같은 회의 이슈 찾기, 스프린트 읽기, Jira 이슈 만들기 | Basic Auth (같은 것. Qello 프로젝트 이슈 만들기·스프린트 보기 권한 필요) |
| 실행 읽기 (실패 알림) | Header Auth (n8n API 키, `execution:read`) |
| 실패 알림, 초안 메시지 고치기 (실패 알림) | Discord Bot |

Discord 봇은 회의 채널의 메시지 기록 보기 권한과 Message Content Intent가 있어야 결정 메시지를 읽는다.

Atlassian 자격 증명은 이렇게 만든다(2026-10-17 사용자 결정: 클래식 API 토큰 1개).

1. https://id.atlassian.com/manage-profile/security/api-tokens 에서 범위 없는(클래식) API 토큰을 만든다. 만료는 최대 1년이라 만료일을 팀 일정에 적어 둔다.
2. n8n Credentials에서 **Basic Auth**를 만든다. User는 Atlassian 계정 이메일, Password는 1의 토큰이다. Basic Auth 자격 증명은 하나만 둔다
   (반영 스크립트가 종류별로 하나일 때만 붙인다).
3. 토큰은 만든 계정의 권한을 모두 가진다. 계정이 바뀌거나 토큰이 새면 1에서 토큰을 폐기하고 새로 만든다.

n8n 화면의 AI 도우미(Connect a model)는 연결하지 않는다. 워크플로와 실행 데이터(녹취 포함)가 모델 제공자로 간다.

## 확인하기

```bash
npm run test:workflow   # Code 노드를 n8n 없이 순서대로 실행, 차이 검사, --check
npm run e2e:n8n         # 실제 n8n 2.42.6 + 가짜 OpenAI·Discord·Confluence·Jira 서버. Docker와 openssl 필요, 비용 없음
```

E2E는 두 워크플로를 모두 가져온다. 실패 알림용 n8n API 키는 테스트 n8n을 띄운 뒤 소유자 계정을 만들어 발급한다.
E2E는 별도 compose 프로젝트(`meeting-bot-gh13-e2e`)와 임시 폴더를 쓰고 끝나면 지운다. Docker volume은 만들지 않는다.
Discord 노드는 주소가 `https://discord.com/api/v10`로 고정이라, 테스트 네트워크 안에서만 `discord.com`을 가짜 서버로 돌리고
실행할 때 만든 테스트 CA를 n8n이 믿게 한다(`NODE_EXTRA_CA_CERTS`). 실패 원인을 보려면 `node scripts/e2e-n8n.js --keep`.

## 넣지 않는 것

자격 증명 값, Webhook 비밀 경로, 서버 주소는 JSON에 넣지 않는다(`AGENTS.md` 3.4). 자격 증명은 n8n 화면에서만 등록한다.
`meeting-ended`는 compose 내부 주소로만 부르는 고정 경로이고 n8n은 서버 `127.0.0.1`에만 열려 있다.
