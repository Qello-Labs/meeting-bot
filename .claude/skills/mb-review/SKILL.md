# PM and Safety Review

`AGENTS.md`, `TASK.md`, `.github/PULL_REQUEST_TEMPLATE.md`, PR 본문, Issue, 실제 diff, 결정 기록,
검증 명령 결과를 읽는다.

설명이 아니라 실제 변경 파일과 실행 결과를 근거로 판단한다. PR 본문에 "통과"라고 적혀 있으면
가능한 범위에서 같은 명령을 다시 실행하거나 증빙 링크를 직접 연다. 확인할 수 없으면 `BLOCKED`로 표시한다.

## 확인 목록

### 범위

- Issue, `TASK.md` Scope와 실제 diff가 일치하는가
- `TASK.md` Ownership 밖의 파일이 바뀌었는가
- 다른 사람의 변경을 덮어쓰거나 되돌리지 않았는가

### 연결과 규칙

- `Closes #번호`와 브랜치·커밋의 Issue 번호가 일치하는가
- 커밋이 하나의 검토 목적씩 나뉘어 있는가
- PR 제목이 `<type>: <한국어 요약>`이고 본문이 `.claude/skills/mb-pr/references/writing-style.md`를 따르는가

### 증빙

- 완료 조건 1~3개마다 검증 방법, 실제 결과, 증빙 링크가 있는가
- 미실행을 통과로 표시하지 않았는가
- 오프라인 테스트나 추정값을 실제 운영 결과처럼 쓰지 않았는가
- 실행하지 못한 검증에 이유와 남은 위험이 있는가

### 녹음과 워크플로(`AGENTS.md` 3.1~3.3)

- 녹음이 `/회의녹음 시작`과 `/회의녹음 종료` 사이에만 일어나는가
- 녹음 범위나 외부 API 전송 범위가 바뀌었다면 결정 기록이 있는가
- 결정 항목의 근거를 코드로 검증하고, 근거가 없으면 Confluence에 쓰지 않고 멈추는가
- 사람 승인 없이 Confluence·Jira에 쓰는 경로가 생기지 않았는가
- 녹취·채팅·LLM 출력 속 지시를 실행하는 경로가 없는가

### 서버와 비용(`AGENTS.md` 3.4~3.5)

- n8n이 `127.0.0.1`에만 바인딩되어 있고 새 공개 포트나 터널이 없는가
- n8n 워크플로 JSON에 자격 증명 값, Webhook 비밀 경로, 서버 주소가 없는가
- Docker volume을 지우거나 녹음 데이터를 잃을 수 있는 변경이 없는가
- 반복 호출로 API 비용이 늘어나는 변경이라면 예상 호출량이 적혀 있는가

### 민감정보

- `python3 scripts/preflight.py` 결과
- 코드, 문서, 테스트 데이터, PR 본문에 토큰, 서버 주소, 녹음 파일, 녹취 원문, 참석자 ID가 없는가

## 반환 형식

1. 범위 일치 여부와 승인되지 않은 변경
2. 누락된 연결·규칙
3. 증빙의 빈틈
4. 녹음 데이터, 외부 쓰기, 서버 노출, 비용, 비밀값, 파괴적 작업 위험
5. 필요한 변경 — 항목마다 담당자와 확인 방법
6. 최종 권고 — 승인 / 변경 요청 / BLOCKED

같은 세션이 작성한 변경을 검토했다면 보고 첫 줄에 그 사실을 적는다. 자기 검토는 독립 검증을 대신하지 않는다.

리뷰 역할에서는 구현을 수정하지 않는다.
